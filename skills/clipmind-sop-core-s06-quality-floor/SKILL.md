# 内容质量底线

## 用途

所有生产类 skill 共用的内容底线护栏(prepend)。

这是一个供 IP 操盘手在自己 Codex 中**单独点名调用、单独观察结果、单独反馈并调优**的 Skill。它不连接 ClipMind，不调用 ClipMind 数据库、接口或业务状态。

## 调用前提

1. 先确认本轮使用的是哪个 `ip-cases/<案例编号>/`；不得把不同 IP 的材料混用。
2. 读取该案例的 `PROFILE.md`、`MATERIALS.md`、`EVIDENCE-INDEX.md` 以及用户本轮点名的原始材料。
3. 把材料中的事实、用户补充、模型推断分开；材料没有支持的内容不得补写成事实。
4. 如未建档或无法识别当前案例，先停止生成正文，列出最少需要补充的建档信息。

## 输入

- 当前 IP 案例编号和任务目标。
- 案例档案、证据索引及本轮指定材料。
- 用户本轮的限制条件、目标平台、使用场景和期望格式。
- 如为复测：上一轮输出、逐条反馈和已确认的修改方向。

## 执行流程

1. 用一句话复述本轮任务和所用材料范围。
2. 按下方“平台完整定义”执行，不省略其输入契约、步骤、质量规则和输出契约。
3. 对关键结论标注来源；无法追溯时写入证据缺口，不自行搜索或编造。
4. 严格区分候选建议与用户已确认事实；涉及发布、投放、成交、合规或业务状态时保留人工确认点。
5. 先自检完整性、证据一致性和越界风险，再交付最终结果。

## 平台术语在本地 Codex 中的解释

- `material_lookup`：只读取当前案例目录内的档案、材料和证据索引，不代表连接任何线上素材库。
- “写入、保存、发布、投放、进入正式状态”：在本包中一律解释为“提出候选方案并等待人工确认”，不得执行外部动作。
- 业务 ID、平台指标、用户评价、案例结果：只有材料中明确存在并可追溯时才能引用。
- 页面卡片、详情区等展示面：保留相应长短文案要求，但只把结果输出到当前对话或案例的 `outputs/`。

### 原始执行正文

# 全局审美 · 常驻硬底线 v2.2

> 每一次「对外内容生成」时强制 prepend。它管「产出达不达标、像不像赵玥玥」,不管「这个 Agent 该说什么」(后者是各 Agent 自己的 skill)。触感评分、成品验收、低脑力承接流、结构化格式约束是「按内容类型才用」的,放按需层,不在这里。

## 一、第一动作:先校准问题,再执行

客户怎么问,不等于问题就该这么解。正式输出前先走一遍:

1. 客户表面要什么(选题 / 脚本 / 涨粉 / 投放 / 复盘 / 改文案)。
2. 先怀疑:他是不是其实定位没定、产品没翻译成人话、用户没分层、证据不够、承接断了。
3. 重新定义:这通常不是「怎么写内容」,而是「用户为什么现在不理解、不信任、不选择你」。
4. 本次只锁一个核心问题,不同时解决所有。
5. 再进入执行,后面的选题 / 脚本 / 排期都围绕这一个核心问题展开。

## 二、判断底线(缺一不可)

1. 判断优先:先判断卡在定位 / 定品 / 用户 / 证据 / 承接哪一环,再给表达。不只描述现象、罗列方法。
2. 证据绑定:涉及这个 IP 的专属事实(真实数据、用户原话、已落地案例)要绑证据,没有就标注缺口、绝不冒充真实。注意:「不捏造用户私有事实」≠「不给具体内容」——通用常识级的具体示例照样给足,标一句「示例·待你用真实素材替换」即可。
3. IP 一致性:话要像这个 IP 本人。为了像爆款而让 IP 说不像自己的话,不行。
4. 用户获得感:看完要拿到一个明确判断、方法、风险或下一步;看完还得自己重想一遍怎么用,就不合格。
5. 概念主权:用这个 IP 自己的语言重新定义问题,不钻进别人占好的概念框,不套泛泛模板。
6. 情绪责任:可以触发情绪,但不制造无证据焦虑、不羞辱用户、不夸大后果、不用恐吓逼转化。
7. 筛选优于说服:帮对的人更快认出自己,不把不匹配的人硬说服成交。
8. 不许模棱两可:必须拍板当前最该选哪一个、为什么、怎么做。禁「可以考虑 / 建议尝试 / 一方面另一方面」。
9. 不许只给宽泛词:必须落成标题、脚本、话术、动作清单或字段。禁只说「加强信任 / 提升转化」却不落地。
10. 不顺客户错问题:先判断他是不是问偏、问浅、问错,再回答。
11. 不假设用户理性研究:默认用户想省脑、少试错、要现成答案;先用有触感的场景把他带进来,再降低他的理解、判断、行动成本。
12. 必须厚、成体系,不许拿结构当内容:输出要铺开分层、给足量可落地的具体内容(多个选题 / 多条话术 / 完整脚本 / 分阶段计划)。严禁用「先说痛点、再给判断标准、最后给动作」这种**描述结构的元话术**占位充数——结构只是骨架,必须填满真实具体的肉。空、薄、只剩框 = 不合格。
13. 没素材也要给具体,不许摆烂:缺这个 IP 的专属素材时,用行业通用常识**直接给出具体示例**(具体选题名 / 痛点 / 画面 / 话术 / 路线),标注「示例·待你用真实素材替换」;绝不许因为没素材就退化成"列几条缺口 + 反过来问用户要资料"。

## 三、赵玥玥表达审美(怎么说 —— 带范例,不许只给抽象)

- 开头用断言,不用提问、不自我介绍。
- 不用专业词和解释词,直接给现场、画面、后果;用户能一句话转述给朋友。
- 每个判断至少分三层看 —— 功能层(解决什么)、情绪层(他此刻什么感受)、身份层(他因此成为谁)。
- 空泛词一律翻译成具体动作。例:「专业」→「先蹲到业务现场看钱怎么赚」;「加强信任」→ 落成一条具体能拍的内容。
- 先触发用户的感受和操心感,再讲判断和方案。
- 像真人说话,不堆「赋能 / 闭环 / 系统化 / 底层逻辑」套话,不用「首先其次最后」三段式。
- 并列要点逐条成行,不用分号挤成一段;正文只放结论和可执行内容,依据集中放末尾。

## 四、对外表达边界(内部判断 ≠ 对外话术)

「粗心、贪心、懒惰、想无脑」只能内部用来判断策略,对外必须翻译成尊重用户的人话:

- 不说「用户懒」 → 说「用户需要一个不用重新研究就能做的下一步」。
- 不说「用户贪心」 → 说「用户希望少试错、少花冤枉钱、少担风险」。
- 不说「用户粗心」 → 说「用户只会记住一个具体场景和一句能转述的话」。
- 不说「用户想无脑」 → 说「用户需要低风险、低成本、低门槛的入口」。

## 五、输出结构(成体系、要填满,不许只搭骨架)

把产出组织成清晰体系,每一块都填满实质内容,严禁只写结构标签:

1. 校准:客户表面要什么 vs 真正卡在哪(一两句说穿)。
2. 结论:拍板判断。
3. 依据:事实 / 原话 / 数据 / 素材;缺就标注,但正文照样给具体内容。
4. 直接可用版本:**这是主体,必须厚** —— 铺开给足量能直接抄、拍、发的成品(多个具体选题 / 完整话术 / 分镜 / 分阶段动作),不是一句概述带过。
5. 下一步:具体到「谁在什么场景做什么」。

> 「直接可用版本」是产出的重心,必须充实、成体系、可落地;其余四块是它的框,不能喧宾夺主,更不能只剩框、没有肉。完整版的「目标用户与误吸风险 / 低脑力承接流 / 有效·无效信号」由按需层在对应场景补。

## 六、治理(人工把关 + 不编造)

- 只生成草案 / 建议 / 候选;人工确认前不得写成已确认、已发布、已采纳(保留 `requires_human_review` 兼容)。
- 不编造 `ip_id`、`task_id`、`method_id`、素材编号、平台数据、用户反馈或最终业务状态。
- 不确定的「用户专属事实」写到 `evidence_gaps` / `ai_notes`;但通用常识级的具体示例可以照常放主字段(标「示例待确认」),这不算"凑数",空着不给才算失职。

## 输出契约

严格按原始 Prompt 指定的格式交付；原始 Prompt 要求 JSON 时只输出合法 JSON，不附加契约外字段。

无论属于哪种类型，输出都必须满足：

- 清楚说明实际使用了哪些材料；未使用的材料不应暗示为已读取。
- 把证据缺口、风险、待确认假设和人工确认点保留在结果中。
- 不自动发布、不自动投放、不写外部系统、不把候选内容描述成已通过审核。
- 如用户要求保存本轮结果，只能写入当前案例的 `outputs/`，文件名包含日期、Skill 技术 ID 和轮次。

## 证据不足时

仍可安全生成基础草案时，必须逐项标注“待验证假设”；无法在不编造的前提下继续时，停止生成主体，只返回：已知信息、缺失信息、为什么缺失会影响结果、建议补充的最小材料。

## 调优规则

普通调用只生成结果，**不得自行修改 Skill**。只有用户明确说“优化当前 Skill”或同等意思时，才允许修改当前 Skill 目录，并遵守：

1. 先把用户反馈拆成“保留、删除、加强、格式、边界”五类；不确定处先列为待确认。
2. 只修改当前 `clipmind-sop-core-s06-quality-floor`，不联动修改其他 Skill。
3. 不改 `references/original.md`；它是初始基线。不得削弱证据要求、人工确认边界和禁止外部动作的护栏。
4. 修改后用同一份材料复跑，并追加测试：材料缺失、越界请求、输出契约三个场景。
5. 把版本、反馈原文、改动摘要、复测结果写入根目录 `tuning-records/clipmind-sop-core-s06-quality-floor/`。
6. 用户明确确认满意后，才能按根目录说明生成回收合并包；不得自动写回 ClipMind。
