# 小月合成内容表现与反馈数据

> **MOCK 合成演练数据**：本文件只用于 Skill Forge 调优。以下平台、内容、曝光、互动与私信数据全部虚构，没有真实后台截图，不得用于外部传播或推断平台规律。

## 数据用途

这组数据只用于比较“小月当前 24 条演练内容”之间的方向信号，帮助策略、缺口、栏目和计划 Skill 练习：

- 不只看曝光，也看有效评论和问题型私信。
- 分清内容表现、用户理解和业务结果。
- 发现高表现内容背后的主题、结构与证据特征。
- 保留样本量、口径和归因限制。

它不能回答“哪种内容一定会火”“内容带来多少成交”“平台用户普遍喜欢什么”。

## 指标口径

| 指标 | 演练定义 | 不能代表 |
| --- | --- | --- |
| 曝光 | 内容被展示的合成次数 | 真实平台分发能力 |
| 3 秒停留 | 短视频播放超过 3 秒的合成比例 | 完整理解或购买意愿 |
| 完读/完播 | 按当前形式完成主要内容的合成比例 | 用户认可所有观点 |
| 收藏 | 用户保存内容的合成次数 | 有效咨询或成交 |
| 有效评论 | 提到自身场景、具体问题或反例的人工分类评论 | 行业总体需求 |
| 问题型私信 | 能描述自己卡在哪一步的人工分类私信 | 付费意愿或成交 |
| 模板索取 | 只询问资料、清单、表格或模板的私信 | 一定是低价值用户 |

所有“有效”均为演练团队人工分类，没有盲审与统一行业标准。

## 同批观察

### 1. 具体诊断比泛概念更容易产生有效问题

D01、D03、D13、D14 的共同点不是形式，而是开头很快出现目标用户和工作现场。评论更容易描述“我也发生过什么”。

这只是当前样本信号，不能推断所有平台都偏好诊断型内容。

### 2. 工具内容的收藏与问题质量不完全同步

D02、D09 收藏高，但模板索取也多。D13 同样是工具内容，因为加入判断场景和使用边界，问题型私信相对更具体。

不能因此得出“模板内容无效”；更准确的判断是，工具内容需要说明何时用、为什么用、不能替代什么。

### 3. 失败案例与拒绝越界能建立另一种信任

D17、D22、D24 没有展示漂亮结果，却产生较多有效评论。用户会追问限制、责任和下一步，说明失败与边界也能承担信任内容角色。

### 4. 长内容需要更快进入现场

D05、D11 前段概念较多，完成率偏低；D12、D20 先展示过程，再展开方法，完成率与有效评论更高。

不能把差异只归因于开头，主题、发布时间、受众和标题也可能影响。

### 5. 产品说明内容不一定追求最大曝光

D21 曝光一般，但问题集中在交付范围和适配条件。它更接近筛选与评估内容，不应只按曝光淘汰。

## 不允许的分析

- 不计算 24 条内容的“行业平均表现”。
- 不把问题型私信当成成交，不计算转化率。
- 不用单条最高曝光决定全部策略。
- 不把 D03、D20 的表现写成某种结构必然有效。
- 不根据平台名称推断真实算法、最佳发布时间或用户画像。
- 不把 MOCK 数字放进课程宣传、案例海报或销售文案。

## 数据缺口

1. 没有真实平台后台截图和内容链接。
2. 不同平台的曝光与完成指标不可直接横向比较。
3. 发布时间、账号基数和付费流量均未记录。
4. 有效评论与问题型私信由团队人工分类。
5. 没有咨询后成交、客单价、复购或收入数据。
6. 没有长期栏目稳定性和跨周期对照。

## 下一轮建议只可作为候选

- 保留诊断、反例、过程示范三类核心栏目。
- 工具内容增加适用边界和使用场景，不全面停掉。
- 长内容用具体现场开头，再展开证据和方法。
- 产品说明以清楚适配和责任为目标，不只追曝光。
- 下一轮补采“用户看完后做了什么”和“哪条证据被质疑”，仍不把相关性写成因果。
