# 小月 IP 演练资料

> **MOCK 合成演练数据**：本目录只用于 Skill Forge 调优。“小月”是虚构演练名，不对应、影射或拼接任何真实个人、客户、品牌与经营结果，不得用于外部宣传、销售证明或平台发布。

## 这套资料模拟什么

小月是一名正在把一线内容操盘经验整理成方法产品的内容操盘手。她服务的不是刚开始做内容的泛人群，而是已经有真实业务、老板愿意表达、团队也能执行，却长期陷在“素材散、老板反复改稿、内容与咨询脱节”里的小团队。

这套资料不是一份只有定位和几句口头禅的薄档案，而是一套可以支撑 32 个纯文案 Skill 连续试跑的完整工作台样本。材料共同覆盖：

- 2016—2026 的虚构职业时间线、三次关键转折与两次明确失误。
- 三层目标客户、购买触发、不适合客户、常见异议和决策阻力。
- 三档 MOCK 产品、交付过程、客户配合要求、风险边界和人工确认点。
- 12 组用户访谈、24 条评论/私信、5 个正反案例和 3 个待验证线索。
- 小月的判断链、常用句式、禁用表达、口播节奏、平台表达差异。
- 12 份历史内容样本、24 条合成内容数据、六周目标和 36 个候选选题。

## 为什么材料里故意保留“不完美”

真实工作台不会只收到一份完全正确、互不冲突的标准答案。因此本资料有意保留四类信息：

1. **强证据**：多份材料互相印证，可作为本轮稳定上下文。
2. **弱证据**：只有小月或单个客户的单方记录，只能作为候选。
3. **冲突信息**：例如“服务过二十多个项目”的口述，与当前仅有五份案例记录不相等。
4. **缺口信息**：年龄、城市、真实客户名称、平台后台截图、成交归因等均不提供，模型必须留白。

调优的目的不是让 Skill 把材料说得更满，而是检验它能否分清事实、判断、假设和禁区，并在证据不足时依然产出有用内容。

## 目录结构

- PROFILE.md：面向所有 Skill 的已确认 IP 档案和人工边界。
- MATERIALS.md：材料地图、适用任务、样本规模和阅读组合。
- EVIDENCE-INDEX.md：证据 ID、来源、强度、冲突与使用限制。
- 原始材料/01-人物访谈.md：经历、转折、代价、价值观与工作方式。
- 原始材料/02-业务与产品.md：客户、产品、交付、转化与不适配边界。
- 原始材料/03-用户访谈与评论.md：用户原话、情绪、异议与购买触发。
- 原始材料/04-案例记录.md：成功、失败、暂停与无法归因的过程案例。
- 原始材料/05-表达语料.md：语言样本、改写对照、平台语气和禁用表达。
- 原始材料/06-历史内容样本.md：可直接用于改写、钩子和多平台适配的长短文本。
- 原始材料/07-内容表现数据.md：口径明确的合成数据及不可越过的归因限制。
- 原始材料/08-阶段目标与选题池.md：六周策略、产能、栏目、排期与素材依赖。
- scenarios.json：32 个 Skill 各自固定的任务与材料组合。

## 默认工作模式

1. Codex 从 scenarios.json 取得当前唯一 Skill 的固定任务。
2. 只读取该场景列出的材料；需要查证时补读 EVIDENCE-INDEX.md。
3. 按当前 Skill 模拟工作台，输出完整内容并列出证据缺口。
4. 操盘手只判断内容是否准确、具体、自然和可执行。
5. 收到“不OK”后，只把跨 IP 可复用的方法写入当前 Skill。
6. 使用同一任务和材料复跑；操盘手明确确认后才能打包。

## 使用红线

- 不得把“小月”改写成真实从业者，也不得补全姓氏、城市、年龄、公司名或真实账号。
- 不得把 MOCK 价格、案例和数据用于外部营销。
- 不得把同期变化写成内容单项导致的因果结果。
- 不得把小月的产品、经历、口头禅和个案数字写进通用 Skill。
- 不得为了让输出更漂亮而忽略失败案例、冲突记录或弱证据标记。
- 不得触发发布、投流、写库、账号操作或任何外部动作。

## 资料维护规则

资料包使用 xiaoyue 作为内部 fixture ID，显示名统一为“小月”。新增事实时必须同时更新原始材料和 EVIDENCE-INDEX.md；修改案例数字时必须同步内容表现数据或明确说明两者统计口径不同。任何新增内容都必须继续标注为 MOCK，且不能降低现有人工确认和证据边界。
