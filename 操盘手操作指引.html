Quick Start · 简单操作指南

调 Skill，
只做四件事

项目已内置赵玥玥 MOCK 演练资料。Codex 会从 32 个纯文案 Skill 中按顺序一次调一个，你只需要看结果，然后告诉它“OK”或“哪里不OK”。

唯一规则
每个 Skill 单独开一个 Codex 对话；全程只使用同一套 IP 材料。
四步完成一次调试
01
用演练资料
Codex 自动装载赵玥玥合成 IP，不需要上传。
02
开对话
复制一句开始口令，Codex 自动找 Skill。
03
给反馈
只说结果哪里好、哪里不对。
04
确认完成
确认 OK，拿到最终 Skill，再开下一个。
01 / 04
Prepare

直接使用内置演练资料

打开项目后不需要导入资料。第一次初始化时，Codex 会自动装载赵玥玥的 MOCK 建档、访谈、产品、用户、案例、语料和内容数据。

默认演练 IP

fixtures / ip / 赵玥玥 /
  • 所有资料都明确标注为 MOCK，不对应真实个人。
  • 每个 Skill 都已经绑定固定任务和材料。
  • 如果素材库已有用户资料，Codex 绝不会覆盖或混入演练数据。

只调文案

治理、共享组件、视觉、生图、发布、监控和数据能力不进入操盘手调优队列。

02 / 04
Start

新建对话，复制一句话

用 Codex 打开整个项目，新建一个对话，把下面这句话发出去。Codex 会自动装载演练资料并开始第一个文案 Skill。

请阅读《开始调试.md》，使用赵玥玥演练资料开始第一个文案 Skill。
  • 不用选择 Skill。
  • 不用复制技术 ID。
  • 不用告诉 Codex 调试顺序。
03 / 04
Feedback

看结果，只回复 OK 或不OK

Codex 输出内容后，会给你两个选项。你只需要判断内容是否达到业务预期。

结果符合预期

OK，完成这个 Skill

Codex 会做最后校验，并输出最终校正好的 Skill。

结果还不满意

不OK：直接说问题

Codex 会只改反馈涉及的部分，再用同一份材料重新生成。

反馈示例

不OK：开头太慢，前三句话没有抓住目标用户；第二部分是对的，请保留。

你只管内容，不用判断哪些 Prompt 能改

Codex 会自动区分“当前 IP 个案”“可写进通用 Skill 的方法”和“不能修改的平台契约”。输入输出字段、工具权限、人工确认和安全护栏不会被改动。

04 / 04
Finish

确认完成，再开下一个对话

你回复 OK 后，Codex 会输出最终 Skill、修改前后差异和校验结果。当前 Skill 到这里结束。

开始调试下一个 Skill

不要在原对话继续调下一个

一个 Skill 对应一个对话，方便保留清楚的反馈和修改记录。新对话会自动读取本地进度，不会从头再来。

FAQ
Questions

常见问题

需要自己挑 Skill 吗？

不需要。Codex 会按 ClipMind 业务顺序自动找下一项。

反馈后要再说“修改 Skill”吗？

不需要。回复“不OK：修改意见”就代表允许它校正当前 Skill。

赵玥玥是真实人物吗？

不是。她是项目内置的合成演练 IP；资料可进入 Git，但不得用于外部宣传。运行副本、私有材料、调试记录和回收包默认被忽略。

确认 OK 后会直接上线吗？

不会。最终 Skill 仍需开发按来源映射复测并人工合入 ClipMind。

That’s all

开对话 → 看文案 → 给反馈 → 确认 OK

操盘手只负责判断内容质量，其他步骤交给 Codex。
